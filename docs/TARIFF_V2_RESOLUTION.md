# Tariff v2 resolution contract

확인 기준일: **2026-09-09**

**상태: v2 구현 완료 후 보존하는 의사결정 기록.** 현재 runtime과 계산 계약은 [TARIFF_POLICY.md](TARIFF_POLICY.md), 남은 작업은 [NEXT_WORK.md](../NEXT_WORK.md)를 따른다. 아래 v1 상태와 v2 구현 순서는 당시 출발점과 판단 기준이며 미완료 TODO가 아니다. 현재는 기후환경·확인된 분기의 연료비·VAT·기금·최저요금·계절별 슈퍼유저요금까지 구현되어 있다.

이 문서는 `src/domain/tariff.ts`의 v1 `excludedComponents`를 해소할 때 사용한 실행 기준이다. **공식 근거가 충분한 항목만 계산에 편입하고 나머지는 명시적으로 제외**한다는 원칙은 계속 유지한다.

## 1. 작업 시작 당시 v1 상태

당시 v1은 다음만 계산했다.

- 주택용(저압)
- 기본요금
- 누진 전력량요금
- 하계/기타계절 구간
- `subtotalWon = baseFeeWon + energyFeeWon`

당시 다음은 `excludedComponents`에 남아 있었다.

- 연료비조정요금
- 기후환경요금
- 부가가치세
- 전력산업기반기금
- 복지할인(구 필수사용량보장공제)
- 1,000kWh 초과 누진할증
- 동계 소용량 할인
- TV수신료

당시 UI 금액은 **기본요금+전력량요금 추정 소계**였다. 현재 v2도 실제 청구액 대비 일정 비율이라고 단정하지 않는다. 특히 `실제 청구액의 약 85~90%` 같은 고정 비율 표현은 사용량, 계절, 연료비, 할인, 할증에 따라 달라지므로 제품/문서 계약으로 사용하지 않는다.

## 3. 공식 근거 우선순위

숫자와 적용기간은 아래 순서로 판단한다.

1. 한국전력 최신 `기본공급약관 및 시행세칙`
2. 한국전력 공지의 분기별 연료비조정단가 산정내역
3. 한전ON의 현재 요금표/요금계산 상세
4. 국가법령정보센터의 현행 법령
5. 찾기쉬운 생활법령정보의 최신 기준일 자료
6. 위 공식 원문을 설명하는 언론/블로그/위키는 **탐색 보조만 사용**하고 숫자 정본으로 사용하지 않음

공식 출처끼리 표기가 다르면 더 최신 시행일의 원문을 우선하고, 그래도 substantive ambiguity가 남을 때만 Discussion Gate를 연다.

## 5. v2에서 반드시 지킬 계산 경계

### 5.1 값의 유효기간

변동 항목은 값 하나를 영구 상수로 두지 않는다.

예:

```text
fuelAdjustment
  2026-07 ~ 2026-09 : +5.0 won/kWh
  2026-10 ~ ?       : 공식 공시 확인 전 미커버
```

분기별 연료비조정단가는 다음 분기 값이 확인되지 않았으면 직전 값을 자동 연장하지 않는다.

### 5.2 기본 no-discount household와 복지할인 분리

표준 예상요금은 우선 **주택용(저압), 복지/대가족/출산/생명유지장치 할인 없음**을 명시적 baseline으로 완결할 수 있다.

복지할인은 사용자 자격이라는 추가 입력이 필요하므로 baseline 계산을 막지 않는다. 자격 입력 기능을 제품에 추가하기 전에는 `미반영 할인 가능`으로 안내한다.

### 5.3 1,000kWh 초과

슈퍼유저 공식 계약이 아직 직접 확인되지 않았다면 1,000kWh 이하 계산을 막지 않는다.

1,000kWh 초과 입력에서 미확인 상태라면 다음 중 기존 UI 구조와 가장 작은 방식으로 처리한다.

1. 정확한 총액 대신 `1,000kWh 초과 할증 미반영`을 명시하거나
2. 계산 결과에 `partial/estimated` evidence를 붙인다.

미확인 상태에서 307.3원/kWh를 무제한 연장하여 `정확한 예상 청구액`처럼 표시하지 않는다.

### 5.4 세금/기금

VAT 10%와 기금 2.7%는 요율이 확인됐다는 이유만으로 즉시 숫자에 더하지 않는다.

편입 전 다음을 현재 공식 자료에서 함께 확정한다.

- 계산 기준이 되는 `전기요금`의 구성
- 할인 적용 전/후 순서
- VAT 원 단위 처리
- 전력산업기반기금 10원 단위 처리
- 최종 청구금액 절사/반올림 규칙

공식 처리 순서를 확인하면 해당 규칙을 tariff domain의 deterministic integer arithmetic으로 구현한다.

## 6. 작업을 멈추지 않는 규칙

다음은 **Discussion Gate가 아니다**. 공식 근거가 한 항목에서 부족하면 그 항목만 제외하고 계속 진행한다.

- 한전ON/약관 첨부를 자동 도구에서 읽지 못함
- 특정 component의 현재 단가만 직접 확인 실패
- 복지할인 상세 matrix 미확인
- 1,000kWh 초과 계절 적용 문구 미확인
- 동계 소용량 할인의 현행 여부 미확인

이 경우 반드시:

1. `unverified` 상태와 마지막 확인 출처/확인일을 문서화
2. 해당 component를 계산에서 제외
3. UI에 미반영 사실 유지
4. 다음 독립 component 또는 테스트/구조 작업으로 진행

다음 경우에만 Discussion Gate를 연다.

- 주택용(저압) 외 계약종별까지 제품 scope를 넓힐지 결정해야 함
- 복지/대가족/출산 등 사용자 자격 데이터를 제품에 저장하는 UX/개인정보 계약이 필요함
- `close month`와 실제 한전 청구월/검침월의 의미가 달라 현재 domain 의미를 바꿔야 함
- 공식 자료끼리 최신 시행 기준으로도 서로 모순되어 하나를 임의 선택하면 청구 의미가 달라짐

## 8. 완료 기준

v2는 모든 세부 할인제도를 구현해야 완료되는 것이 아니다.

최소 완료 기준은:

- 주택용(저압) standard no-discount household에 대해 공식 근거가 확인된 component만 계산
- 각 변동 component가 명시적 effective window와 source/retrieved date를 가짐
- 확인되지 않은 component는 값 추정 없이 excluded/partial로 남음
- 1,000kWh 초과가 미확인 상태일 때 정확한 총액으로 오인시키지 않음
- UI는 계속 `예상 전기요금`임을 표시하고 미반영 항목을 노출
- tariff 계산은 usage domain과 분리
- 경계/계절/분기/반올림/미커버 window 자동 테스트
- repository 전체 Verify 신규 회귀 없음
- VERSION/tag/release/main 통합/deploy 없음

이 기준이면 한전 공식 페이지 한 곳이 자동화에서 막혀도 **확인 가능한 범위를 끝까지 구현·검증하고, 미확인 항목만 좁게 남긴 상태로 회차를 정상 마감**할 수 있다.
